# Telegram-бот фильтр трафика (Traffic Splitter / преленд)

Сегментация входящего трафика по возрасту и полу с маршрутизацией на целевые
каналы, пофамильной аналитикой по байерам и точным учётом подписок.

Стек: **Python 3.12 · aiogram 3.15 · PostgreSQL · Redis · Alembic · Google Sheets API · Docker Compose**

---

## Что сделано по пунктам ТЗ

| № | Требование | Реализация |
|---|---|---|
| 1 | Реферальные ссылки, индивидуальные на каждого заливщика | `ref_links` + `buyers`, deep link `t.me/<bot>?start=<code>`. Ссылки создаются в админке, код генерируется из названия (транслит кириллицы, коллизии получают суффикс) |
| 1 | Статистика по каждой ссылке: Start / фильтр / подписка | Трёхэтапная воронка считается SQL-агрегацией по `users`, с процентами от Start и от фильтра. Срезы: сегодня / 7 дней / 30 дней / всё время; по ссылкам, по байерам, по сегментам, по каналам |
| 2 | Точный подсчёт подписчиков с конкретной ссылки | Инвайты создаются с `creates_join_request=True`; бот перехватывает `chat_join_request`, одобряет заявку и привязывает подписку к `telegram_id` → к реф-ссылке. Не «+1 подписчик», а конкретный юзер |
| 2 | Бот-администратор канала | Нужно право «Добавление подписчиков». При назначении админом канал сам появляется в админке, бот сообщает, хватает ли прав |
| 3 | Сценарий `/start` → возраст → пол → канал | `app/handlers/funnel.py`, сообщение редактируется на каждом шаге (чат не засоряется) |
| 3 | 4 сегмента → 4 канала | `app/services/routing.py`. Несколько каналов на сегмент с приоритетами и весовой ротацией |
| 3 | «Не подходит аудитория <18 → отсеивать и отдавать на другой канал» | Флаг `allow_minors` у канала — жёсткий предохранитель: канал 18+ **никогда** не выдаётся детскому сегменту, даже если его туда привязали по ошибке. Дальше три уровня фолбэка, иначе заглушка |
| 4 | Полная база юзеров | `users`: ID, username, имя, ответы, сегмент, ссылка входа, назначенный и фактический канал, статус подписки, даты. Плюс сырой лог `events` и история офферов `offers` |
| 4 | Google Sheets, раздельные базы по аудиториям | Листы: `Сводка`, `Коротко`, `Парни 18+`, `Девушки 18+`, `Младше 18`, `Без фильтра`. Синхронизация фоновая, пачками, по флагу `needs_sheet_sync` — ответ юзеру никогда не ждёт Google API |
| 4 | Excel | Выгрузка XLSX из админки той же структурой |
| 5 | Push-уведомления по выбранным ответам | Рассылка с фильтрами: пол, возраст, статус (прошёл фильтр / не подписался / подписался / бросил фильтр), конкретная реф-ссылка, конкретный канал |
| 5 | Медиа + текст + URL-кнопки | `copy_message` — переносит любой тип (фото, видео, GIF, кружок, голосовое) без пометки «переслано», плюс инлайн-кнопки |

Сверх ТЗ, потому что без этого продакшен больно: отписки откатывают конверсию
(`chat_member`), рассылка держит rate-limit и продолжается с курсора после
рестарта контейнера, заблокировавшие бота исключаются из выборок, байер может
смотреть свою статистику сам (`/stats`, `/mylinks`).

## Как работает учёт подписок

Главная техническая развилка ТЗ — «считать точное количество подписчиков с
определённой реф-ссылки». Счётчик подписчиков канала этого не даёт: он не знает,
кто пришёл. Поэтому:

```
юзер прошёл фильтр
   └─> бот создаёт инвайт с creates_join_request=True
        └─> юзер жмёт «Вступить» → заявка, а не моментальный вход
             └─> бот получает chat_join_request с from_user.id
                  ├─ approve_chat_join_request()
                  ├─ users.is_subscribed = true, subscribed_channel_id = N
                  ├─ offers.status = joined
                  └─ конверсия падает в статистику его реф-ссылки
```

По умолчанию на канал создаётся одна join-request ссылка и кэшируется в БД:
атрибуция всё равно точная, потому что `from_user` приходит в событии. Если
нужны персональные ссылки на юзера (например, чтобы ловить вирусные пересылки) —
`PER_USER_INVITE_LINKS=true`, но это +1 запрос к API на каждого юзера.

## Быстрый старт

Развёртывание на сервере — отдельной инструкцией: [DEPLOY.md](DEPLOY.md).

```bash
git clone <repo> && cd tg-filter-bot
cp .env.example .env
# впишите BOT_TOKEN и ADMIN_IDS
docker compose up -d --build
docker compose logs -f bot
```

Миграции применяются автоматически при старте контейнера (`alembic upgrade head`).

### Локально без Docker

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
cp .env.example .env            # DB_DSN можно указать sqlite+aiosqlite:///./bot.db
.venv/bin/python -m alembic upgrade head
.venv/bin/python -m app
```

### Настройка каналов

1. Добавьте бота администратором в каждый целевой канал с правом
   **«Добавление подписчиков»** (`can_invite_users`).
2. Канал сразу появится в `/admin → 📢 Каналы` как черновик, бот напишет,
   хватает ли прав.
3. Откройте канал в админке, отметьте сегменты, при необходимости разрешите
   `<18`, включите канал.

Либо залейте каналы пачкой: заполните `channels.example.json` и укажите
`SEED_CHANNELS_FILE=channels.example.json`.

### Google Sheets

1. В Google Cloud: создайте сервисный аккаунт, включите **Google Sheets API**,
   скачайте JSON-ключ в `secrets/google.json`.
2. Расшарьте таблицу на e-mail сервисного аккаунта с правом редактора.
3. В `.env`: `GOOGLE_SPREADSHEET_ID=<id из URL таблицы>`.

Листы создаются сами. Если Sheets не настроен — бот работает как обычно,
синхронизация просто выключена.

## Админка (`/admin`)

```
📊 Статистика   — воронка по ссылкам / байерам / сегментам / каналам, 4 периода
🔗 Ссылки       — создать одну или паком, выдать deep link, выключить, статистика
📢 Каналы       — сегменты, allow_minors, вес ротации, пересоздать инвайт
👥 Байеры       — добавить (можно с Telegram ID — тогда он сам смотрит /stats)
✉️ Рассылка     — фильтры → сообщение → кнопки → предпросмотр → запуск, прогресс
📤 Экспорт      — XLSX, ручная синхронизация и полная перезаливка Sheets
```

Команды байера: `/stats`, `/today`, `/mylinks` — только его ссылки.

## Структура

```
app/
├── __main__.py          точка входа: DI, воркеры, graceful shutdown
├── config.py            настройки из .env (pydantic-settings)
├── enums.py             сегменты, статусы, типы событий
├── db/
│   ├── models.py        buyers, ref_links, channels, users, offers, events, broadcasts
│   └── repo.py          все запросы к БД, включая SQL-агрегации воронки
├── handlers/
│   ├── funnel.py        /start → возраст → пол → оффер
│   ├── join.py          chat_join_request, отписки, назначение бота админом
│   ├── admin_*.py       разделы админки
│   └── buyer.py         личная статистика байера
├── services/
│   ├── routing.py       сегмент → канал (приоритеты, веса, фолбэки, защита <18)
│   ├── invites.py       join-request инвайты
│   ├── broadcast.py     рассылки: лимитер, курсор, блокировки
│   ├── sheets.py        фоновая синхронизация Google Sheets
│   └── export.py        XLSX
└── keyboards/, middlewares/, utils/
migrations/              Alembic
tests/                   209 тестов
```

Одна сессия БД на апдейт (`DbSessionMiddleware`), одна транзакция, коммит на
выходе из хендлера. FSM в Redis; если Redis недоступен — бот не падает, а
переходит на in-memory хранилище с предупреждением в логе.

## Тесты

```bash
.venv/bin/python -m pytest -q      # 209 passed
.venv/bin/python -m ruff check app tests migrations
```

Что покрыто:

* **Маршрутизация** — все 4 сегмента, запрет 18+ каналов для `<18`, фолбэки,
  приоритеты, весовая ротация.
* **Сквозные прогоны через настоящий `Dispatcher`** (`tests/test_integration_funnel.py`)
  с мок-сессией Telegram: `/start` с реф-ссылкой → фильтр → оффер с join-request
  инвайтом → `chat_join_request` → конверсия в статистике; отписка; повторный
  `/start`; `/reset`; отсутствие каналов; сбой создания инвайта; доступ в админку.
* **Воронка на БД** — пример из ТЗ (Start 100 → фильтр 80 → подписка 45) с
  проверкой процентов, разбивка по ссылкам и байерам, периоды.
* **Рассылки** — попадание только в выбранный сегмент, блокировки, остановка на
  середине, продолжение с курсора после рестарта, кнопки.
* **Миграции** — `alembic upgrade head` даёт схему, побайтово совпадающую с
  моделями (защита от дрейфа), и чисто откатывается.
* **Клавиатуры** — все собираются, ни один `callback_data` не превышает лимит
  Telegram в 64 байта.

## Эксплуатационные заметки

* Фильтр возраста — **самодекларация** (как и просили в ТЗ). Это не проверка
  возраста, поэтому каналы для сегментов `<18` должны быть реально
  безопасными для подростков, а `allow_minors` у взрослых офферов — выключен.
  Предохранитель в коде не даёт перепутать это случайно.
* Лимит рассылки по умолчанию 20 msg/s (`BROADCAST_RATE`), Telegram начинает
  давать 429 около 30. `TelegramRetryAfter` обрабатывается с ожиданием.
* Повторный `/start` по другой ссылке **не** переписывает источник — иначе
  статистика первого байера уехала бы ко второму.
* `AUTO_CREATE_UNKNOWN_LINKS=false` по умолчанию: ссылки выдаёт админ, а
  неизвестный `?start=код` не создаёт строку в отчёте — иначе опечатка в
  креативе размазывает трафик байера по двум «ссылкам». Код перехода при этом
  сохраняется в `users.ref_payload` и виден в выгрузке, а юзер попадает в
  строку «Без ссылки (органика)». Включите `true`, если заливщики должны
  придумывать коды сами, не дожидаясь админа.
